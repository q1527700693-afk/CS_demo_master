# 服务器密钥与网页版发布

SSH 私钥是管理员连接服务器的凭据，正常网页或应用运行完全不需要它。防止用户提取的根本方法是：**不把服务器私钥发送给任何客户端**。前端代码、混淆、加密后连同解密代码一起打包，或藏在安装包/资源文件中，都不能可靠保密。

本次密钥仅通过原路径供 SSH 使用；不打印内容，不进入 frontend/public、Vite 环境变量、源码仓库、构建产物或安装包。Windows OpenSSH 拒绝权限过宽的原文件，因此连接时使用临时副本：仅授予当前管理员读取，结束后恢复删除权限并删除副本。不改动原文件。服务器上已有 `.env` 不读取、不复制、不覆盖。

推荐落地：

1. 密钥留在管理员工作站、SSH agent 或受限的部署机上；文件 ACL 仅限管理员，设置口令。不要放入应用文件夹、聊天记录附件下载目录的发布包或公网静态目录。
2. 服务端模型 API Key 只放后端环境/密钥管理服务中；不要使用 `VITE_` 前缀。浏览器只持用户自己的会话凭据，由后端鉴权并转发模型请求。
3. 部署使用独立的最小权限账号，SSH 安全组只允许管理员 IP；服务进程用非 root 用户运行，禁止网页提供通用 SSH/命令执行接口。
4. 若该私钥曾进入 Git、安装包、公网文件或不可信收件人，删除副本不能收回已泄露密钥；应更换服务器授权公钥并吊销旧凭据。
5. 当前站点使用 HTTP。上线正式账号与 AI 服务前建议配置域名和 HTTPS，保护用户会话。SSH 私钥无需也不应下发到网页。

浏览器中的公开展示草稿是本人设备上的普通摘要，不包含 SSH/模型密钥。公开展示权限必须最终由服务器控制，不能把 localStorage 开关当成服务端鉴权。
