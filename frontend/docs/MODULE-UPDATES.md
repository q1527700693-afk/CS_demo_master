# 模块更新与扩展说明

所有已有功能都保留了更新入口。模块注册入口为 `src/app/modules.ts`，路由和侧栏从这份配置生成；业务页面、API 适配层和游戏挂载保持分开。更新一个功能时，优先只改它自己的文件。

## 已有模块怎么更新

| 功能     | 页面或容器               | 对接入口                            | 更新方式                                                         |
| -------- | ------------------------ | ----------------------------------- | ---------------------------------------------------------------- |
| 总览     | `src/features/overview/` | 复用复盘 API、登录状态              | 修改汇总展示；关闭复盘时停止请求和隐藏相关入口                   |
| 登录注册 | `src/features/auth/`     | `auth/api.ts`、`src/stores/auth.ts` | 替换认证 API 适配，保持共享登录状态与原路由名                    |
| 个人资料 | `src/features/profile/`  | `profile/api.ts`、共享用户类型      | 修改资料字段和保存 API；同步更新登录状态中的用户资料             |
| 玩家名片与好友 | `src/features/player/`、`social/` | 已实现的 `getPublicProfile`；`social/api.ts` 中待协商草案 | 名片展示独立更新；好友搜索和关系只占位，接入前先与后端确认协议 |
| 复盘     | `src/features/replay/`   | `replay/api.ts`、`src/types/`       | 分别更新上传、任务状态、报告页；保留原链接中的报告 ID            |
| 校园车队 | `src/features/lobby/`    | `lobby/api.ts`、`src/types/`        | 更新列表、创建、加入与退出接口和页面                             |
| 瞄准训练 | `src/features/training/` | 原游戏 `mountTrainer` / `destroy`   | 更新队友源目录，通过同步脚本复制运行资源；游戏内容无需改写为 Vue |

表中的 API 文件路径均位于相应 `src/features/` 目录下。网络请求复用 `src/api/http.ts`，身份复用 auth store，避免各功能自己维护另一份登录。
登录、个人资料和公开名片已按 `dev` 的实现接入；车队和复盘继续使用前端建议协议及模拟占位。好友搜索/关系按要求只留界面和接口草案，不模拟。具体边界见 [API-CONTRACT.md](API-CONTRACT.md)。

## 模块未完成或需要暂时关闭

复制 `.env.example` 为 `.env.local`，按需设置：

```dotenv
VITE_FEATURE_REPLAY=true
VITE_FEATURE_PROFILE=true
VITE_FEATURE_LOBBY=true
VITE_FEATURE_TRAINING=true
VITE_FEATURE_SOCIAL=true
```

设置某一项为 `false` 后，该模块的导航和总览入口隐藏，直接访问旧链接显示“暂未开放”，不加载该模块的业务页面。总览和登录作为基础入口保持开放。
资料关闭后仍能登录和退出。复盘关闭后，总览不再请求复盘 API。功能开关只控制前端可用性，后端仍需正常鉴权和权限检查。

`VITE_MOCK_AUTH` / `PROFILE` / `REPLAY` / `LOBBY` 决定对应请求使用模拟数据还是真实后端，与功能启用开关独立。例如车队页面已经完成但后端未完成时，可以保留功能开放并继续模拟车队请求。
环境变量在启动/构建时读取，修改后重启开发服务；正式环境重新构建并发布。

## 新增一个功能

1. 在 `src/features/<名称>/` 放页面、局部组件和 API 适配函数。
2. 在 `src/app/modules.ts` 添加一条 `FeatureModule` 配置，包括唯一 `id`、标题、`enabled`、路由，以及可选导航项；导航通过 `order` 排序。
3. 页面组件使用 `moduleView(() => import(...))` 按需加载。网络中断或发布后旧页面文件不可用时，会显示刷新重试页面，公共导航仍然可用。
4. 需要登录的路由保留 `meta: { requiresAuth: true }`，使用现有 auth store。新增字段先和后端约定，再补充类型和相应模拟处理。

例如新增独立的反应测试页面，可以在 `features/reaction/` 放容器，然后注册 `/reaction`。如果队友提供的是完整独立网页模块，可参照训练的挂载/销毁适配；不需要把游戏内部逻辑重写进公共布局。

路由地址和路由名尽量保持稳定；需要改地址时为旧地址保留重定向。后端新增字段优先使用可选字段，已有字段改变含义或类型时需要约定新的版本或在 API 适配层转换，避免波及全部页面。

## 更新队友的游戏

1. 将队友更新后的文件放到 `../training/CSPlatform/aim-trainer`，保留原公开挂载接口。
2. 执行 `npm run training:sync`；`npm run dev` 和 `npm run build` 启动时也会自动同步。
3. 浏览器刷新训练页面，检查五种模式、资源加载、历史记录及离开页面后的资源释放。

同步脚本按字节复制并记录 SHA-256，不改动原游戏。源文件在开发服务启动后发生变化时，需要再次同步并刷新；重新运行构建也会同步。
原游戏历史仍按原方式保存在浏览器本地。宿主通过 `onComplete` 为当前登录账号另存本机名片最佳，账号隔离且不自动认领原共享历史。云端适配仍需先与后端约定，当前没有伪造云端成绩接口。
如果游戏更新改变了原挂载接口或本地数据结构，需要同时调整容器或由游戏作者提供数据迁移。完整边界见 [GAME-INTEGRATION.md](GAME-INTEGRATION.md)。

## 发布一次更新

运行 `npm test` 和 `npm run build`，将新的 `dist/` 完整发布到 HTTP 服务。后端继续使用已确认的接口契约；前端 URL 需要回退到 `index.html`，API 请求优先转发给后端。
发布建议先上传新资源再切换入口，并暂时保留旧版本资源，减少正在使用旧页面的用户加载失败。更新失败提示只处理页面加载失败，不会自动回滚版本或恢复未保存的表单。

这里的“保留更新能力”是代码、接口和资源可以继续替换和扩展，不是已经实现独立在线热更新。当前没有远程插件安装、应用内补丁下载、自动更新服务器或桌面安装包更新服务；以后若需要这些能力，可在现有模块边界上另行接入。
